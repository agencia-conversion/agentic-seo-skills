# Editorial

Sample Project usa uma linha editorial curta para validar se o Companion organiza conteúdo, clusters e páginas do brain sem depender de texto vazio. A fixture não representa autoridade de mercado; ela representa cenários previsíveis para testes de interface e persistência.

## Área editorial: Companion e governança

- slug: companion-governanca
- tese: interfaces editoriais precisam preservar Markdown autoral e decisões rastreáveis.
- diferenciação: exemplos mínimos que exercitam funções reais do Companion.
- audiência: agentes e revisores que validam fluxos de brain e conteúdo.

## Do's

- Usar exemplos pequenos e auditáveis.
- Conectar conteúdos publicados a [[topic-clusters]].
- Explicar estados da interface com linguagem direta.
- Registrar decisões relevantes em [[log]].

## Don'ts

- Inventar prova externa para dados de fixture.
- Criar wikilinks para páginas inexistentes.
- Deixar páginas canônicas sem corpo.
- Confundir cenário de teste com posicionamento de cliente.
